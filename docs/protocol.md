# 通信协议

三层：**空口帧**（Quest ↔ C5）→ **SPI 帧**（C5 ↔ F411）→ **遥测帧**（F411 → C5 → 串口）。

---

## 1. 空口帧（16 字节，小端）

由头显侧发出（BLE 或 WiFi），C5 收。

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | magic | `0xA55A`，**小端字节序为 `5A A5`，首字节 0x5A** |
| 2 | 2 | yaw_cdeg | 偏航角，单位 0.01° |
| 4 | 2 | pitch_cdeg | 俯仰角，单位 0.01° |
| 6 | 2 | yaw_rate | 偏航角速度，单位 0.1 °/s |
| 8 | 2 | pitch_rate | 俯仰角速度，单位 0.1 °/s |
| 10 | 4 | seq | 序号，递增 |
| 14 | 1 | flags | bit0 = 有效数据 |
| 15 | 1 | 保留 | |

校验：末 2 字节为 CRC16-CCITT（poly `0x1021`，init `0xFFFF`），覆盖前 14 字节。

> ⚠️ **最容易踩的坑**：magic 写成 `0xA5 0x5A`（大端顺序）会让 F411 永久收 0 帧，且没有任何报错。第一次联调时这个错误排查了很久。

---

## 2. SPI 帧（C5 → F411，31 字节）

C5 把空口帧重打包成 `qp_head_t`（30 字节）后通过 SPI 发出。

```
┌────────┬────────┬────────┬─────────┬───────┐
│ magic  │ ver    │ seq    │ yaw/pitch│ CRC16 │
│ 2 B    │ 1 B    │ 1 B    │  ...     │ 2 B   │
└────────┴────────┴────────┴─────────┴───────┘
```

- 传输长度 **31 字节**（多 1 字节给从机的残留字节）
- F411 在 ISR 里逐字节收，先补 DR 再处理缓冲
- 解析时前 3 字节内搜 `A5 5A`，命中后按偏移取字段

---

## 3. 遥测帧（F411 → C5，30 字节）

`f411_stat_t`，C5 解析后打印到串口。

| 字段 | 含义 |
|---|---|
| magic | `A5 5A` |
| frames | F411 收到的帧数 |
| lost | 丢帧数（`seq` 差值累计） |
| crc_err | 编码后的两轴应答计数 |
| tick_ms | F411 时间戳 |
| yaw_cdeg / pitch_cdeg | 编码器实测角度 |
| mode | 运行模式（见下表） |
| spi_err | SPI 错误计数 |

### 模式字节

| 值 | 含义 |
|---|---|
| 0x06 | 上电使能 / 清零中 |
| 0x07 | **正在限位校准** |
| 0x08 | **校准跑完但没撞到任何限位**（电机没电 / 没接线 / 地址错） |
| 0x03 | 演示模式（DEMO） |
| 0x04 | 跟随模式（TRACK） |

串口输出示例：

```
I bridge: F411 TRACK | 收 450 帧 | 丢 0 | 应答 2200/2198 | pos 12.4° / -3.1°
I ble_test: BLE 收 2340 回显 2340 失败 0 | 连接已连 | 间隔 30.0 ms
```

## 4. 图传（PC 中转）

```
采集卡 → ffmpeg → MJPEG over HTTP → App / 网页
```

| 端点 | 说明 |
|---|---|
| `/stream.mjpg` | multipart/x-mixed-replace，连续帧 |
| `/snapshot.jpg` | 单帧 JPEG |
| `/report` | 页面回传调试信息 |

`devserver.py` 环境变量：

```powershell
$env:HT_OUT_W="1280"; $env:HT_OUT_H="720"; $env:HT_OUT_FPS="60"
$env:HT_Q="6"                 # 2(最好)~8(最小)
$env:HT_IN_FMT="yuyv422"      # 这块 UGREEN 95348 只认 yuyv422
```
